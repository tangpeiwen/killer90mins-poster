## 1. 要解决的问题

每期海报只换：五位演员的照片、姓名、主持人标签位置、日期时间；第五格可切换为神秘嘉宾剪影。其余版式完全不变。

此前用 AI 逐版调整（`_run_update_0829` → v3 → v5 → v7 → v8 → v10），始终无法收敛。

## 2. 根因

不是 Illustrator 的精度限制（它可定位到 0.001pt），是三个可消除的缺陷：

**2.1 关键输入靠目测。** 人像发顶位置是决定垂直位置的唯一变量，此前由模型看图估计。实测：`四、Caleb.png` 的 alpha 通道第一个非透明行是 **399**，而 `_calibrate_all_portraits_from_caleb_v10.jsx:15` 里人工试出的值也是 `399/3796`——**八个版本、两天时间，重新发现了一个 5 行代码 200 毫秒能算出的数**。同批的 Chin Wang（598）、JORGE（432）差 5 个百分点，目测不可能同时猜准。

**2.2 系统没有不动点。** 既有脚本同时移动名牌和人像，且用 `tag.visibleBounds` 当人像的定位基准。基准本身在动，被基准定位的对象也在动——**这个迭代数学上不收敛**。

**2.3 校验是自证的。** `_fix_portrait_head_gap_v8.jsx:29` 输出 `verified_gap_mm=12.0`，但它校验的是自己的算术；输入错时它同样输出 12.0，零信息量。

## 4. 摆放规则

### 4.1 已确认（实测支持）

| 规则 | 实测证据 |
|---|---|
| **R1** 名牌角度 = 该格黑板上沿角度 | 五格误差 ≤ 0.11°（矩阵仅两位小数，实际应为精确相等） |
| **R2** 名牌横向居中于黑板 | 偏差 −0.89 / −0.29 / +0.66 / −0.68 / −0.81 mm |
| **R3** 人像头部横向居中于黑板 | 偏差 +0.85 / −1.54 / −0.18 / −0.45 mm（JORGE −4.89，侧头） |
| **R4** 名牌墨迹下边 → 人像轮廓，**最小垂线净距 = 12 mm** | 11.38 / 11.72 / 11.39 / 12.52 / 11.31，均值 **11.66**，极差 **1.21 mm** |

R4 是全部数据中最紧的一组，且在"垂线"与"垂直"两种约定下都成立（垂直读数均值 12.20，极差 1.85）。**该规则可直接采用，不依赖约定之争。**

> **R4 的取样方式是关键。** 人像轮廓是曲线、名牌下边是斜线，两者最接近处不在头部中心——实测在名牌宽度的 19%–50% 处，每格不同。必须沿名牌下边**逐列扫描取最小值**；按固定列取样会系统性偏大 1.7–3.9 mm。

|---|---|---|---|
| ACTOR_01 ian | 15.28 | 15.43 | 13.87 |
| ACTOR_02 kent | 14.82 | 15.72 | 12.68 |
| ACTOR_03 chin wang | 14.35 | 15.58 | 12.72 |

三种量法极差均为 4.3–5.4 mm。**上下沿是平行线，垂直间距沿 x 恒定，不存在取样位置问题——该离散是文件的真实状态，不是量法造成的。**

设计师规格为 12 mm。已生成 `_apply_uniform_12mm.jsx` 供其目视裁定。

**待设计师回答：** 上侧统一到 12 mm 是否可接受？若是，R5 = 12 mm 垂线；若否，R5 = 冻结 v3 现状（每格一个常量）。

**该项不阻塞开发**：名牌位置与演员无关，是每格固定的模板几何；R5 只是 L1 常量表里的一个数。

### 4.3 缩放基准（未定）

实测头宽 64.7 / 66.6 / 63.3 / 63.5 mm（四人聚在 ~64 mm），但 CHIN WANG 量出 79.2 mm——alpha 的"头宽"把长发两侧算了进去。

长发、帽子会破坏该指标。**这是全流程唯一 alpha 通道无法胜任、需要人脸检测的地方**（改用眼距或头顶–下巴，对发型免疫）。

临时方案：沿用现有缩放，只改位置。

### 4.4 「发顶」的规范定义（关键）

**本节是全文最重要的约束之一。**

「发顶」在亚毫米尺度上**没有唯一解**。三种都合理的定义在同一批素材上相差 1–2 mm：

| 定义 | ian | kent | chin wang | caleb | jorge |
|---|---|---|---|---|---|
| alpha > 16 | 11.26 | 11.02 | 10.50 | 11.78 | 11.19 |
| alpha > 128 | 11.33 | 11.10 | 11.32 | 11.84 | 12.16 |
| 渲染图 L>20 且连续 20 行 | 11.40 | 11.73 | 12.16 | 12.53 | 12.15 |

差异来源是**发丝的半透明过渡带**。硬边素材（帽子、光头、短发）过渡 1–3 行；蓬松长发过渡 9–12 行。alpha 通道顶端的平均值实测：

```
caleb        13 → 229 → 240 → 241     硬边，1 行完成过渡
ian 帽子      42 → 104 → 175 → 217     3 行
chin wang     6 →  16 →  47 →  98     40 行仍未到 100
jorge        10 →  29 →  53 →  80     同样很缓
```

`alpha > 16`（6% 不透明度）会把**渲染出来接近纯黑、肉眼不可见**的发丝算作发顶。

**规范定义（L2 必须实现）：**

> 发顶 = 沿列扫描，`alpha ≥ 128` 的像素连续覆盖 ≥ 源图高度 0.1% 的第一行。

选它不是因为它"正确"，而是因为它**可执行、可复现，且最接近肉眼**（ian / jorge 残差 0.01–0.07 mm）。

**推论：容差必须放宽。** 定义本身有 ±1 mm 的固有模糊，验收标准写 ±0.3 mm 是自欺欺人。见 §8。

### 4.5 测量方法的两个坑（已踩过）

1. **最小净距必须按整数列迭代，一列只算一次。** 若按连续坐标步进再取整映射到列，多个坐标会落到同一列并用不同的直线位置反复比较，产生虚假的更小值——实测把取样步长从 1.0 pt 改到 0.5 pt，结果变化达 0.7 mm。修正后换取样密度的差异降到 0.003–0.02 mm。
2. **渲染图上的轮廓检测不要用长游程。** 要求「连续 N 行非黑」会把发顶系统性下压 N 行；在 11.8 px/mm 的图上 N=20 即 1.7 mm 偏置，且随发丝密度变化。

### 4.6 头部居中的规范定义

**规则 R3 的可执行版本。** 表述为「头部到黑板两侧的距离相等」而非「头中心 = 黑板中心」——两者等价，但前者是**两个可测距离的相等关系**，因此不需要给绝对毫米数（各人头宽不同，认可稿实测 63.2–77.5 mm，左间距因而从 14.3 到 19.8 mm 不等）。

**「头部两侧」必须定义在头部最宽处。** 不这样定义时，量测高度会带来最多 10 mm 的分歧：

| slot | 发顶下 8% | 12% | 16% | 20% | 极差 |
|---|---|---|---|---|---|
| ian | 1.49 | −0.91 | −2.21 | −2.21 | 3.70 |
| kent | −6.85 | 3.13 | 2.42 | 2.42 | **9.98** |
| chin wang | −1.73 | 0.08 | 1.97 | 2.05 | 3.78 |
| caleb | −0.89 | −1.10 | −1.10 | 1.13 | 2.23 |
| jorge | −9.87 | −9.18 | −0.86 | −0.86 | **9.00** |

头顶弧面上（8%）头发向一侧梳会让轮廓严重偏斜；太阳穴/耳朵一圈（16%+）才稳定。

**规范定义：**

> 头部最宽处 = 从发顶往下 5%–20% 图高范围内，`alpha ≥ 128` 的轮廓中**最宽的那一行**。忽略与主体水平分离超过 3% 图宽的块（麦克风、举起的手）。
>
> 验收：`|左间距 − 右间距| ≤ 4 mm`

该定义**对搜索范围不敏感**——[3%,22%]、[5%,20%]、[5%,25%] 三种窗口给出完全相同的结果，因为「最宽处」是真实解剖特征而非人为百分比。实测最宽处落在发顶下 10.7%–15.5%，五人一致。

认可稿实测左右差值：**−1.98 / +4.21 / +2.05 / −1.17 / +2.19 mm**。容差 4 mm 即「与设计师手工水平持平」；若要更严可取 2.5 mm。

**容差的用途是抓 bug，不是卡精度。** L3 直接把最宽处中心对齐黑板中心，差值应接近 0；一旦跳到 10 mm 以上，通常意味着素材异常（举手、麦克风贴脸），需要人工看一眼。

**教训：** 本节的定义确定之前，笔者曾用「发顶下 12%」量出 jorge 差 9.18 mm 并据此报警。改用最宽处后实测为 +2.19 mm——**那是误报**。定义不清的验收标准既会漏报也会误报。

## 5. 四层架构

| 层 | 职责 | 运行频率 | 出错时改哪 |
|---|---|---|---|
| **L1 版面标定** | 从模板读黑板几何、上沿角度、目标间距 → `slots.json` | 换模板才跑 | 改 json 一个数 |
| **L2 素材测量** | 从 PNG alpha 算 `headTopRatio` / `headCenterXRatio` / `headWidthRatio` → `actors/<id>.json` + 标注核对图 | 每张新照片一次，永久缓存 | 改 json 一个数 |
| **L3 摆放** | 读 L1+L2+brief，**纯算术，零判断，零分支**。永远从模板跑，绝不从 v(n-1) | 每次出图 | 不改（它没有可调项） |
| **L4 复检** | 导出 PNG → 在真实像素上量净距与居中 → 通过/失败表 + 标注图 | 每次出图 | — |

### 5.1 唯一纪律

> **L4 失败时，回去改 L1 或 L2 里的一个数字。永远不许再写一个 v11 补丁脚本。**

这条规则是防止 v3→v10 重演的全部机制。

### 5.2 L2/L3 边界

L2 用 Python（PIL/numpy）读 alpha 并输出 JSON；L3 用 JSX 应用。**所有算术在 Python 侧完成，JSX 只做赋值。** `_apply_uniform_12mm.jsx` 已按此形态生成——脚本体内没有一个计算表达式。

理由：ExtendScript 无法读 PNG alpha，且调试成本高；把判断与计算集中在可测试的一侧。

### 5.3 L4 的可行性说明

导出图上，名牌白块（L≈250）与纸面（L≈244）**不可分**；但名牌压在黑板（L≈1）之上，限定在黑板内检测即可可靠分割。人像轮廓对黑板同样可分（发色最暗约 L≈30）。已验证可行。

## 7. 模板需修复的问题

按严重程度：

1. **中文名丢失白色印章板。** 白块是 `La Machine Company` 的**字形自带**，非独立图形对象。中文回退到 `Huiwen-MinchoGBK-Regular` 后白块整体消失（见 `预览2.jpg` 的「凌 浩」），且墨迹内缩 3.5–4.3 mm，是拉丁名的 1.5 倍。**中文名必须单列规则或另配带白块的中文字体。**
2. **NAME 内容为小写**（`"ian"` `"kent"` `"chin wang"`）。既有 skill 文档要求写成大写 `CHIN WANG`——**若大写字形无白块，该指令会直接毁掉名牌。落地前必须验证。**
3. `ACTOR_03/PHTOTO` 拼写错误（全部版本均有）。
4. `0805/killer90mins_v3.ai` 的 ACTOR_03 含一个**宽度为 0 的空文字对象**，坐标 `-2526.74` 位于画板外，轮廓化返回垃圾值。
5. **字号随名字长度手工变动**（54.25 默认 / 49.19 chin wang / 45.61 secret guest），规则未明文。
6. **PHOTO 内部结构在版本间漂移**：0805 为嵌入 RasterItem + 多一层矩形剪切；0819 为链接 PlacedItem + 单层剪切。

## 8. 验收标准

每次出图后由 L4 自动断言：

- 名牌墨迹下边 → 人像轮廓最小垂线净距 = 12.0 **± 1.0 mm**（五格）
  - 容差取 ±1.0 mm 而非 ±0.3 mm：见 §4.4，「发顶」定义本身有 ±1 mm 固有模糊，更严的容差没有物理意义
- 头部最宽处到黑板左右两侧的距离，差值 ≤ 4.0 mm（定义见 §4.6）
- 名牌横向中心与黑板中心偏移 ≤ 1.0 mm
- 名牌角度与该格上沿角度差 ≤ 0.2°
- 人像四边覆盖黑板，底部出血 ≥ 1.0 mm
- 静态图层（STATIC）字节级未改动

## 9. 不做的事（YAGNI）

- 不做通用海报引擎，只服务这一个模板
- 不做 GUI
- 不在第一版引入人脸检测（见 4.3，等缩放基准定案）
- 不重构既有 `_run_update_*` / `audit_*` 脚本，它们作为诊断历史保留

## 11. 统一 12mm 试做的实测结论（2026-08-23）

`_apply_uniform_12mm.jsx` 已执行，产出 `killer90mins_v3_12mm.ai/png`。L4 在导出 PNG 的真实像素上复核：

| slot | 下侧 修改前 | 下侧 修改后 |
|---|---|---|
| ian | 11.40 | 12.05 |
| kent | 11.73 | 11.97 |
| chin wang | 12.16 | 12.67 |
| caleb | 12.53 | 12.31 |
| jorge | 12.15 | 12.92 |
| **均值 / 极差** | **12.00 / 1.13** | **12.38 / 0.95** |

**结论一：R4 在 v3 中本已达标。** 修改前均值 12.00 mm，极差 1.13 mm，落在 §8 容差内。设计师已把这一侧做到位。

**结论二：本次下侧改动应回滚。** 均值漂移到 12.38 mm，因位移量基于 `alpha>16` 的发顶（见 §4.4），对蓬松发质多推了约 0.8 mm。

**结论三：本次唯一有效的变化是上侧**（15.3 / 14.8 / 14.4 / 12.5 / 11.0 → 五格 12.00 mm）。若要请设计师裁定上侧，应重出一版**只改上侧、下侧保持 v3 原样**的对照图，避免两个变化混淆判断。

**结论四：这是 L4 的首次实战价值。** 脚本无报错、离线自检五格全绿，但真实像素显示下侧退步。若仅凭脚本输出判断，该缺陷会直接进入生产。

### 12.2 容差必须从认可稿反推（本次实际发生的错误）

验收脚本第一次运行时**没能通过设计师认可稿**：

| 项 | 认可稿实测最差 | 初次拍定的容差 | 结果 |
|---|---|---|---|
| R2 | 11.45 ~ 12.56 | 12 ± 1.0 | ✅ 通过 |
| R3 | **+4.21**（kent） | ≤ 4.0 | ❌ 差 0.21 |
| R1 | **−1.25**（jorge） | ≤ 1.0 | ❌ 差 0.25 |

R1 出错的原因具体而典型：早先量 R1 用的是**文字框中心**（≤0.89mm），验收改用**墨迹中心**后变成 1.25mm，容差没有同步。

修正为 R3 ≤ 5.0、R1 ≤ 1.5，写入 `config/slots.json` 并附推导依据。

> **规则：容差取「不严于人工水平」。验收脚本必须先能通过认可稿，否则它是在拿一把认可稿自己都过不了的尺子量东西。**

### 12.3 缩放基准：五种度量全部试过

| 方法 | 认可稿上的极差 | 失败原因 |
|---|---|---|
| **轮廓头宽** | **14.3 mm** | 长发会撑宽 ← 现行方案 |
| 头高（发顶–下巴） | 25.3 mm | 高领毛衣测不出脖子，轮廓从头到肩不收窄 |
| 肤色宽（脸宽） | 15.1 mm | 胡子、眼镜切断肤色区 |
| Haar 人脸框 | 平均偏 8.3 mm | 含 2 次误检；戴帽者偏 22.9mm |
| 双眼中点 | 平均偏 6.6 mm | 5 张里 3 张检不出 |

§4.3 曾判断「长发和帽子需要人脸检测」——**该判断被数据推翻**：恰恰是帽子和眼镜让人脸检测失效，而轮廓法完全不受影响。

**结论：不引入人脸检测。** 现行方案为默认 64.4mm + 每位演员一次性人工覆盖（写在 brief 里，永久缓存，演员复用时不需重判）。

一度提出「肤色宽/轮廓宽 < 0.70 则放大 20%」的启发式，**已否决**——被眼镜和胡子污染（CASPER 比值 0.605 实为眼镜所致，并非头发）。

### 12.4 边缘羽化：本项目栽过四次

黑板与名牌的边缘在导出图上都有抗锯齿过渡带（`244→235→180→120→60→1`）。四次误判分别是：把上沿羽化当成名牌、把名牌自身羽化当成人像轮廓、把纸面当成白块、把下沿羽化当成透明缝。

**这是 §5.3「L4 像素检测可行」判断的实际反例。** L4 最终改为读 `.ai` 对象坐标，不读像素——见 §12.5。

### 12.5 L4 的最终形态与独立性边界

L4 = 只读审计 JSX 读回 `.ai` 实际状态 → Python 配合 `actors/*.json` 重算。

**能抓到**：公式错、slot 映射错、JSX 赋值静默失败、链接没换、模式没切。
**抓不到**：几何公式本身错、alpha 定义错（与 L3 共用），以及「对象位置对但渲染异常」。前两者靠 §4.4 §4.6 的规范定义与本文的推导锁定；后者极罕见，需要时用诊断导出（临时把黑板改成品红再导图）抽检。

### 12.6 仍未做

- ~~幂等性测试~~ **已完成，见 §14。**
- **日期横向重排**：`AUG` 比 `SEPT` 窄约 34mm，字间距会变。两份认可稿的日期是每期手工摆的，无可反推的对齐规则，故未自动化。**设计师未就此提出问题，暂不处理。**
- **头宽搜索窗口按图片高度取 5%–20%**，对顶部裁切极紧的照片会整体下移到脸的下半部（ayin 的最宽行落在嘴的高度）。改用「头部高度」百分比更对，但依赖脖子检测，高领毛衣测不出来。

## 14. 幂等性验证（2026-08-26）

### 14.1 为什么单独测

v1→v10 的失败本质就是幂等性的反面：每版在上版结果上改，状态累积，同一起点跑两次得到不同结果，
错了回不去。幂等的管线可以**任何时候从母版重跑，无需知道之前发生过什么**。

### 14.2 先修掉的隐患：相对位移

原 stage2 对两类对象的处理方式不一致：

```
人像   p.width= p.height= p.left= p.top=    绝对赋值 → 幂等
名牌   tf.translate(dx, dy)                 相对位移 → 跑两次会叠加
```

它当时之所以安全，靠的是脚本里的文件名检查（只允许对 `..._s1.ai` 运行）——
**幂等性依赖一道防护，而不是设计本身**。防护是会被改掉的。

改为从 stage1 测得的 `text_gb` 加位移得出**绝对坐标**后，全脚本无任何相对操作。

### 14.3 结果

| 层 | 方法 | 结果 |
|---|---|---|
| L2 素材测量 | 同一照片测两次 | ✅ json 逐字节相同 |
| L3 脚本生成 | 同一 brief 生成两次 | ✅ JSX 逐字节相同 |
| **Illustrator 执行** | **同一 s1 跑两次 stage2 + 审计** | **✅ 导出 PNG 逐像素相同（0 / 15,431,472）** |

L4 报告有 **1 行**差异：ACTOR_04（中文名）的 `ink_gb` y 坐标差 **0.0004 pt**，
折算到 R0 是 **0.000133 mm，容差的 0.013%**。x 坐标、四个 `photo_gb`、其余三格 `ink_gb`、
日期、HOST 徽章全部逐字节一致。

### 14.4 一个值得记的观察

**唯一的差异在「测量工具」里，不在产物里。**

`createOutline()` 对中文字体的轮廓转换有微米级不确定性，但实际画面逐位相同。
也就是说：**只看 L4 报告会以为有 0.0004pt 的抖动，看 PNG 才知道产物根本没变。**

推论：判断幂等性时，**产物的字节比测量报告更可信**——测量本身也是一次计算，会引入自己的噪声。
