# 「量化」不是判据，「可判定 + 有来源」才是

用户在第 1 课后自行总结出「好的 skill 应该有可量化的验收标准」，方向正确但用词回到了
「量化」——而这正是他早先被我修正过一次的说法。已再次用他自己的数据校准：
`v10` 脚本的 `faceX: 0.406023` 六位小数、第一版 skill 的 `12mm ± 2mm`，
两者都高度量化且都无用。判据是两问：**这个数从哪来** + **跑完谁来判定**。

**Evidence**：用户主动提出「什么是居中，以及如何判定我做完的结果符合标准」——
后半句已经触到正确判据，只是前面挂了「量化」这个标签。属表述回退，非理解回退。

**同时补充了两点用户尚未覆盖的**：

1. **验收救不了结构性错误。** 第一版让名牌与人像互为参照且同时移动，
   该迭代无不动点、数学上不收敛。完美的验收只会诚实地报错十次，
   不会指出"这个解法根本没有解"。写 workflow 时要单独问：
   有没有两个东西互为参照还同时在动？
2. **眼睛不是被禁止，是被分配。** 重写版仍保留人眼环节（L2 核对图），
   区别在于明写出来、且缩小到眼睛擅长的判断。用户原话「而不是我肉眼去看」略微过头。

**Implications**：
- 三条腿（可判定的验收 / 数字有来源 / 系统有不动点）中，第 3 条用户尚未内化，
  且它最难自查。下一课或下下课应专门处理"识别没有不动点的系统"。
- 用户已能自行推导「静默失败 vs 响亮失败」的适用边界（此前我给过，他复述准确）。
- 第 1 课的作业（圈出别的 skill 里"凭感觉"的条目）尚未提交，下一课的改写练习应基于它。
