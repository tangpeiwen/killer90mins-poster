规则可执行性检查表

给任意一条 skill 里的规则做体检。三十秒一条。

一、主判据

跑完之后，谁来判断这一条满足了没有？

答案只有三种，写下来就行：
一段能跑的代码 · 一个明确指定的人在看明确指定的东西 · 没想过

第三种是要修的。第二种合法 —— 但必须写出来，藏起来的人工环节最致命。

二、四个快速嗅探

出现这些词问自己
大约 / approximately
尽量 / 视情况		 这个模糊是真的必要，还是我当时没测？大多数时候是后者。
看起来 / visually
合适 / 自然 / 协调		 换个人看会得到同样结论吗？换个时间我自己看呢？
一个具体数字 它从哪来？测的 / 从认可样本反推的 / 人拍板的 —— 三选一，写在旁边。
答不上来就是编的。没有来源的数字，下一个人会顺手改成整数。
保持 / 对齐 / 居中
距离 N 毫米		 这里藏着一个测量问题。量哪两条边？在什么位置量？边界怎么定义？

三、把"无判定"改成"有判定"

手法怎么做例子
定义边界把模糊的名词换成可复现的算法 “visible face” → alpha ≥ 128 连续覆盖 ≥ 图高 0.1% 的第一行
标注来源每个数字后面写它从哪来 12.0 ± 1.0mm（认可稿实测 11.45–12.56）
给参照物没有硬指标时，锚到一个稳定的外部样本 “和这三篇的语气一致”“和上一版的目录结构一致”
列反例正面难定义时，写死不许出现什么 “不许改动 STATIC 图层”“不许出现这五类表达”

四、容差怎么定

从认可样本反推，取"不严于人工水平"。

不要凭印象拍。实际发生过：容差拍成 4.0mm，而设计师认可稿实测最差 4.21mm —— 等于拿一把认可稿自己都过不了的尺子在量东西。

验收脚本必须先能通过认可样本。通不过，先修尺子，别改产物。

五、三个稳定器（按重要性）

#要求自检
1每条规则都有独立的判定 验收和执行是两个东西吗？脚本自己打印"通过"不算数。
漏检的规则等于没有规则。写完验收，逐条对照规则清单。
2每个数字都有来源 随机抽三个数字，能说出它从哪来吗？
3系统有不动点 有没有两个东西互为参照、还同时在动？
有的话那个迭代数学上就不收敛，再精确也没用。

六、什么时候必须写验收

失败的方式例子要不要写
响亮编译不过、脚本报错、API 返回 400环境自带验收，可省
静默海报差 3mm、数据少一行、配置写对了但没生效 必须写 —— 它看起来是对的

再叠一条：这个 skill 会被反复调用吗？会 → 收益按次数累积。 两个都占的，验收标准比方法本身还重要。
